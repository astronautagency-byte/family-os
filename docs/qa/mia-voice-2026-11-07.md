# Mia dialogue and natural voice

Screenshot reproduction: “Add 330 haircut to my events for calendar” was not recognized locally; a subsequent “add lemons” could be routed back to the online assistant instead of preparing a grocery draft.

Changes:
- Parse compact times at the start of explicit calendar requests, preserving the event name. Keep day/time/AM-PM separately; ask one missing detail at a time without assuming a date or period.
- Merge short answers into the existing event draft. Parse explicit new requests in every conversation mode. Preserve manual review and confirmation before any write.
- Read final recognition results only, display interim text without preparing an action, request up to three recognition alternatives, and accept a parsable alternative without executing it.
- Short spoken Fam AI responses ask one focused question and retain supplied details. Failure recovery does not repeatedly route direct additions through a failed assistant call.
- Natural speech uses Groq Orpheus English, Hannah, through authenticated `mia-speech`. Fixed voices/provider endpoints, 600-character bound, server-side household usage allowance, finite timeouts and no-store responses. User text/audio/key are not logged or saved by FamOS. Keys stay server-side. Device speech selects an enhanced/natural installed voice on failure, with visible fallback notice.
- Browser audio is unlocked by the user gesture and microphone listening resumes only after playback ends. Closing, backgrounding and ending a conversation cancel playback/listening. Natural voice has a visible control and processing disclosure.

Live service checks: after the owner configured a Groq key from the enabled account, `mia-speech` returned HTTP 200, voice Hannah, with 169030 bytes of valid 24-kHz PCM WAV (about 3.52 seconds) for a synthetic greeting. A second request returned HTTP 200 with 107590 audio bytes. A Fam AI voice request with a missing haircut day returned HTTP 200 and “Which day would you like to schedule the haircut?” No customer data was used.

A Safari microphone/acoustic/device playback test is still a separate acceptance check; parser and simulated recognition/playback regressions are covered locally. Browser automation was stopped at the user's request; release verification proceeds through CLI/HTTP.
